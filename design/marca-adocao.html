A regra que sustenta tudo: o lima é claro demais para carregar texto branco. Ele entra como fundo, sempre com forest por cima. É por isso que o botão primário fica lima com letra escura — e não o contrário. Já existe um teste travando isso: nenhum variante pode usar o lima como cor de texto.

O que isso custa no código. As telas de entrada já usam as variantes novas — foi só trocar o variant de cada botão. Para as demais, o caminho é trocar o padrão do Button compartilhado, como o app do cliente fez: lá 24 telas mudaram de uma vez. Medi o risco aqui: apenas 2 chamadas passam cor de fundo própria sem dizer a cor do texto, e as duas ganham textColor="$white" no mesmo commit. O resto já declara as duas coisas.

O que continua diferente do app do cliente — e por quê. Lá o botão tem variant: solid | outline | destructive; aqui ainda é bg/textColor por prop, em 42 chamadas. Igualar a API exigiria reescrever todas — trabalho que se perde, porque estas 13 telas viram NwButton na migração. A convergência real de componente acontece quando o cliente migrar para NativeWind (o C15 do handoff). Até lá, igualamos o resultado visual: mesma cor, mesma altura, mesma fonte, mesma hierarquia.
